# Настройка владельца NoSale Django Admin без слабых паролей

**Использовать только на изолированном SaaS `nosale.svdev.pro`**, не на legacy продавце.

Права superuser не выдаются при регистрации, по домену почты, по URL или по угадыванию существующей записи. Команда дополнительно требует, чтобы SaaS работал в режиме `SAAS_PIN_AUTH_ENABLED=1` и `REQUIRE_EMAIL_VERIFICATION=1` — иначе выдача прав запрещена. На staging сейчас нет superuser, и адрес владельца `owner@svdev.pro` **не зарегистрирован** — по этой причине самовольная выдача прав запрещена.

Порядок:

1. Владелец регистрирует свой почтовый адрес на `nosale.svdev.pro` через существующий email-код и PIN, затем проверяет обычный вход.
2. Надёжный оператор на сервере задаёт точный адрес в закрытом `saas/.env` как `NOSALE_OWNER_EMAIL=<actual-owner-email>`. **Не хранить это в Git, не указывать чужую/предзаполненную почту в публичной форме**. Убедиться, что переменная реально попала в окружение **только SaaS web-контейнера** после безопасного обновления конфигурации; редактирование `.env` без перезапуска процесса недостаточно.
3. В SaaS web-контейнере выполнить сухой прогон `python manage.py provision_owner_admin --email <actual-owner-email>`. До подтверждения он **не изменяет БД** и требует, чтобы активная запись с совпадающими `username=email` и установленным PIN уже существовала.
4. После авторизованного подтверждения владельца выполнить `python manage.py provision_owner_admin --email <actual-owner-email> --confirm` **однократно**. Команда идемпотентна, записи пользователя и секретов не создаёт.
5. Владелец входит тем же email+PIN через `/login/`, затем открывает `/admin/`. AI/тарифные настройки доступны только `is_superuser`. По умолчанию AI OFF, Smart price OFF / банк OFF, включать только после approval.
6. Проверить `User.is_staff/is_superuser` лишь для подтверждённой существующей записи, журналы административных действий, штатный logout. Отзыв — отдельное явное административное действие. Не запускать `createsuperuser --noinput` с известным паролем.

**Тесты:** пустой allowlist, несовпадающий адрес, отсутствие учётной записи, неактивный пользователь, ненастроенный PIN, дубли email, dry-run и повторный запуск, доступ к реальному Django admin после подтверждения.

**Релизный блокер:** команда не заменяет регистрацию владельца и реальную проверку входа. Не допускается раскрывать email/API токены через кабинет клиента.

Источник: `saas/billing/management/commands/provision_owner_admin.py`, R3 owner admin #10.
