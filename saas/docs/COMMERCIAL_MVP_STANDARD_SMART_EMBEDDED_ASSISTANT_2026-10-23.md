# NoSale — первый коммерческий MVP: два тарифа и встроенный веб-помощник

**Дата:** 2026-10-23. **Приоритет:** релиз Standard + Smart с работающим помощником **внутри сайта NoSale**. Источник правды по очередности: [RELEASE_IMPLEMENTATION_PLAN_STANDARD_SMART_2026-10-23.md](./RELEASE_IMPLEMENTATION_PLAN_STANDARD_SMART_2026-10-23.md).

## Уточнённое решение владельца

Ранее была неверно понята формулировка «взять ассистента из Телеграма и воткнуть его в базовую версию». Нужен **переиспользуемый ассистент в кабинете NoSale**, не новый Telegram-бот, Telegram login или delivery канал. Используем подходящие наработки существующего Telegram-ассистента, но интерфейс, контекст магазина, авторизация и платёжная проверка полностью принадлежат NoSale.

**Standard** (планируемая цена ~500 ₽/мес.): действующая детерминированная защита скидок, страницы товаров/настроек, события и предупреждения, **базовый веб-помощник** по использованию сервиса и состоянию собственного магазина. Базовые информационные ответы желательно получать без внешней LLM, когда это возможно. Если AI используется и в Standard — owner-configured малая квота и стоимость обязательны.

**Smart** (планируемая цена ~990 ₽/мес.): всё из Standard; расширенная роль **того же веб-помощника**, использующая подтверждённые факты его WB магазина, 1–2 содержательные рекомендации/сводки в день (не обязательно, если нет событий), до 2 ответов на пользовательские вопросы в день на первом этапе. AI Platform Gateway/DeepSeek, управление моделью и квотами через owner Django admin; никакие API keys LLM клиент не вводит.

Цены — гипотезы до согласования владельцем, платежей и фискализации. Обычный Telegram-бот и подключение Telegram пользователем **не входят** в MVP.

## Что переиспользовать

- `Anderhaos/MiniBook/backend/src/modules/tg-admin-assistant`: базовые подходы к интентам, сессиям, объяснениям, безопасности и обработке ответов. **Не переносить** Telegram transport, BotFather, webhook, CRM/YCLIENTS команды или user identities.
- `Anderhaos/platform-kits/packages/ai-runtime`, `Anderhaos/ai-platform`: существующую маршрутизацию LLM, учёт токенов и стоимость, реально опубликованные модели. Если есть verified internal project gateway — Django вызываeт его через служебную авторизацию, без дубля провайдерского SDK.
- `Anderhaos/MiniBook/backend/src/modules/billing`: pattern `effective AccessGrant -> capabilities`; не копировать работу PRO checkout без проверки, т.к. текущий BeClients отключает покупку PRO.
- `saas/guard/advisor.py`: текущий factual read-only advisor. Требует SKU-level freshness и подтверждённые версии источника, затем может служить evidence payload для Smart.

## Что должен делать помощник

**Standard** — интерактивная область/чат на экране NoSale, без отдельной регистрации. Ответы на «что делает контроль», «когда проверялся мой магазин», «есть ли предупреждения», «как настроить лимит» из правил, наблюдений и проверенной справки. Если данных нет — честный ответ. При необходимости LLM для формулировки/свободного текста через owner budget.

**Smart** — те же типовые вопросы плюс «какие SKU требуют внимания», «что изменилось за сутки», «какие неподтверждённые операции», «что проверить в первую очередь». Числа вычисляются backend и сопровождаются временем наблюдения; модель формулирует пояснения, но не придумывает объёмы продаж, скидки за счёт WB, выгоду или прибыльность. AI write не разрешён.

Сводки по изменению фактов, ограниченный quota ledger per user, без WB polling ради AI, без хранения чужих профилей и no collective training при отсутствии явных прав.

## Админка и экономика

В существующем Django `/admin/`: тарифы и месячные цены, effective `AccessGrant.plan`, capabilities, gateway health, model selector, prompt version, owner-only usage/expenses, per-user limits, global AI disable. Секреты в серверном secret store; не в браузере или репозитории. `Standard` guard не зависит от работоспособности AI.

Не плодить дополнительную entitlement таблицу: `SubscriptionPayment.plan + approved fixed amount` фиксируются при покупке, signed verified Tochka approval создаёт `AccessGrant.plan`, effective capability проверяется на каждом запросе. Изменение тарифа/возврат не создаёт скрытого доступа. Trial сохраняет Standard.

## Порядок

1. **R1** — полноценный billing на два тарифа: выбор, цена, оплата, доступ, возврат, срок, upgrade.
2. **R2** — встроенный базовый web assistant из переносимых возможностей имеющегося ассистента.
3. **R3** — owner admin, provider role/model/quota/cost; параллельно R2.
4. **R4** — Smart grounded advice и questions в **том же веб-чате**, до двух сводок.
5. **R5** — E2E через браузер, PostgreSQL, WB/read-only, AI Gateway, bank sandbox, staging rollout и закрытая бета.

Отдельный Telegram-бот и большая собственная аналитическая база — **позже и только при отдельном решении**. Основной критерий релиза: **зарегистрировался → подключил WB → выбрал тариф → открыл помощника прямо на сайте → получил корректную помощь/рекомендацию по своему магазину**, без Telegram.

**Статус:** это продуктовый контракт и план, НЕ подтверждение реализованного чата/AI. Не менять живого продавца на legacy `mpnosale.svdev.pro` и не включать реальную оплату без отдельной приёмки.
