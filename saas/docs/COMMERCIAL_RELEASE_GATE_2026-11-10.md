# NoSale — коммерческая релизная приёмка (10.11.2026)

Актуальные задачи: [#12](https://github.com/Anderhaos/Marketplace-Price-Guard/issues/12) и [#11](https://github.com/Anderhaos/Marketplace-Price-Guard/issues/11). По **последнему контракту Smart** — плановые советы и краткие DeepSeek-сводки, **не свободный чат**. Старый путь /assistant/ намеренно ведёт в ленту уведомлений. Устаревший план от 23.10 нельзя использовать, чтобы самовольно включать ручной чат или MCP-вызовы из него.

## Как проверить без воздействия на продавцов и банк

Из действующего NoSale web-контейнера:

```sh
python manage.py nosale_release_check
python manage.py nosale_release_check --json
python manage.py nosale_release_check --require-public-go
```

Последняя команда **завершится ошибкой**, пока не подтверждены внешние факты: это правильный fail-closed результат. Команда не делает API запросов, не запускает WB-проверку, не выставляет счета, не включает тарифы и не сохраняет данные.

Её зелёные локальные проверки означают только, что известные настройки и записи соответствуют техническим условиям; **не означают завершение релизной приёмки**.

## Отдельные независимые доказательства перед Public GO

- WB: юридическое разрешение на коммерческий SaaS, действующие scopes, лимиты, работа нового seller-токена и изоляция доступа.
- Точка: Standard и Smart реально куплены отдельно картой и СБП; правильная цена, чек, verified webhook, AccessGrant и срок. Возврат через **owner UI**, банковский статус REFUNDED, чек возврата, связанный AccessGrant отозван. Старый ручной возврат в самом банке не заменяет новую проверку.
- AI: фактический доступ Smart, явное согласие, запланированная сводка DeepSeek по своему магазину, бюджет/cap и отказ без согласия. Не выдавать синтетический тест за живого платящего пользователя.
- Риски: privacy/оферта, внешняя зашифрованная резервная копия и проверенный restore, права owner/tenant, CI Django/PostgreSQL/Chrome **по финальному SHA**, независимый review, сохранённый rollback.
- Owner: отдельное документированное решение GO после приёмки. В тикете #12 хранить обезличенные ссылки и статусы; не публиковать JWT, чеки с персональными данными, WB-токены и PIN.

Публичные предложения Standard / Smart в PostgreSQL **оставить выключенными** до завершения всех пунктов. Закрытая бета — отдельное ограниченное разрешение, не автоматическое включение продаж.
