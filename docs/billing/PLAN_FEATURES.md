# NoSale — конструктор возможностей тарифов

Владелец: `/admin/control/tariffs/` → Standard / Smart → «Доступные функции тарифа».

Переключатель «Продажи включены» отвечает **только за новые платежи**. Чекбоксы
возможностей немедленно определяют права **текущих** пользователей с активным
`AccessGrant` этого плана, включая пробный. Условия оплаты, срок гранта,
разделение продавцов, права владельца, секреты WB/банка, серверные разрешения
на операции, AI-бюджет и отдельное пользовательское согласие не обходятся.

Ключи (стабильные identifiers):
- `discount_guard` — выполнение проверок/исправлений WB и редактирование правил
- `notifications` — уведомления, ежедневные дайджесты, Web Push (с проверкой перед отправкой)
- `activity_history` — история проверок и журнал товара
- `promotion_audit` — аудит акций Wildberries
- `finance_audit` — финансовые отчёты WB (разрешение на отзыв своего ключа сохраняется)
- `store_advice` — скриптовые рекомендации/сводки (могут быть включены для Standard)
- `ai_advice` — DeepSeek-резюме только поверх `store_advice`, дополнительно требует согласие,
  включённую AI Platform и лимиты расходов

Флаги независимы: Smart может не содержать Smart-рекомендаций, Standard может
их получить. `ai_advice` без `store_advice` не инициирует модель.
План без активного гранта не получает возможностей независимо от конфигурации.

`OwnerTariffOffer.features = NULL` означает сохранение прежнего набора
до первого изменения владельцем: Standard — основная защита, уведомления,
история, акции и финансы; Smart — всё перечисленное плюс рекомендации и AI.
Пустой список `[]` означает **все функции выключены**, а не набор по умолчанию.
Проверка неизвестных ключей выполняется сервером, незнакомые значения не
добавляют прав. Исторические платежи и временные гранты не переписываются.

Изменения применяются на следующем запросе/цикле воркера. Для критичных
производственных случаев отмены функций, особенно защиты скидок и Push, владелец
должен учитывать мгновенные последствия для активных подписчиков.

Проверка выпуска: Django/PostgreSQL/Chrome CI, миграция, owner POST,
Standard/Smart, отказ прямого GET/POST, активный WB worker, срок подписки,
согласие пользователя на AI, отсутствие новых платежей или токенов.
